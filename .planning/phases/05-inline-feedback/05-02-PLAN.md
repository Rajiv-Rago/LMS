    **1. Create `components/lesson/FeedbackSection.tsx`:**

    A client component ("use client") that renders the always-visible feedback form. Props:
    ```typescript
    interface FeedbackSectionProps {
      onSubmit: (feedback: string) => void;
      creditsRemaining: number;
      disabled: boolean; // true when generating or no credits
      generating: boolean;
    }
    ```

    Implementation details:
    - Heading: "Something wrong with this lesson?" in `text-lg font-medium`
    - **Suggestion chips** rendered as a row of buttons above the textarea: "Too advanced", "Too basic", "Outdated info", "Unclear explanation". Styled as pill buttons (`rounded-full px-3 py-1 text-sm`) with indigo outline, hover fill. Clicking a chip sets the textarea value to the chip text and sets a `chipSelected` boolean to true.
    - **Textarea**: rows=3, placeholder "Describe what's wrong or how this lesson could be improved...", max 500 chars. On change, if user edits, clear `chipSelected` flag (so validation re-applies). Show character count.
    - **Validation**: On submit, if `chipSelected` is false and text length < 10, show inline error "Please provide at least 10 characters of feedback". If `chipSelected` is true OR text length >= 10, call `onSubmit(feedbackText)`.
    - **Submit button**: Text = `"Improve with AI (${creditsRemaining} left today)"` when credits > 0. Text = `"No credits left -- resets tomorrow"` when credits === 0. Disabled when: `disabled` prop is true, or credits === 0, or validation fails. Style: `bg-gradient-to-r from-indigo-600 to-violet-600 text-white` (matches AI gradient from branding).
    - When `generating` is true, the entire form shows as disabled with reduced opacity.
    - Form resets textarea to empty after `onSubmit` is called (parent handles the actual submission; reset happens on prop change or parent callback).

    **2. Modify lesson page** (`app/(dashboard)/courses/[id]/modules/[moduleId]/lessons/[lessonId]/page.tsx`):

    a. **Update Permissions interface** to include `isSharedWith: boolean`.

    b. **Add new state variables:**
       - `creditsRemaining: number` (initialized to 0)
       - `undoAvailable: boolean` (false)
       - `undoTimer: ReturnType<typeof setTimeout> | null` (null)

    c. **Fetch credits on mount**: Add a `useEffect` that fetches `GET /api/ai/credits` on mount. Parse response and set `creditsRemaining`. Only fetch if user has feedback permissions (canEdit or isSharedWith). Handle errors silently (default to 0).

    d. **Replace `canGenerate` logic**: Change from `isOwnedCourse && permissions?.canEdit` to `const canFeedback = isOwnedCourse && (permissions?.canEdit || permissions?.isSharedWith)`. Use `canFeedback` for showing the FeedbackSection. Keep `canGenerate` (or rename) for the skeleton "Generate" button that appears when generationStatus is "skeleton" (first-time generation -- this is separate from feedback regeneration and should remain canEdit-only since it is initial content creation, not feedback).

    e. **Modify `handleGenerate` function**:
       - After the POST returns 202 and the job polling completes successfully (job status "completed"):
         1. Re-fetch the lesson (existing `fetchLesson()`)
         2. Decrement `creditsRemaining` by 1 locally
         3. Set `undoAvailable = true`
         4. Start a 30-second timeout that sets `undoAvailable = false`
         5. Show success via the undo bar (not toast -- undo state is local)
       - After the POST returns non-200 (error):
         1. If 429: update creditsRemaining to 0, show error toast "No credits left -- resets tomorrow"
         2. Other errors: show error toast "Regeneration failed. Try again later."
         3. Do NOT show skeleton loader -- content stays as-is (per pitfall #6 in research)
       - Critical: Show skeleton only AFTER the POST returns 202 (job enqueued), NOT on button click. Between click and 202 response, show a spinner on the submit button only.

    f. **Add undo handler** (`handleUndo`):
       - POST to `/api/courses/ai/${id}/lessons/${lessonId}/revert` with CSRF header.
       - On success (200): re-fetch lesson, set `undoAvailable = false`, clear timer, show toast "Lesson reverted".
       - On failure: show error toast "Failed to revert. The previous version may no longer be available."

    g. **Render undo bar**: When `undoAvailable` is true, render a floating bar at the bottom of the lesson content area (not using the toast system). Style: fixed-position or sticky bar with "Lesson updated" text + "Undo" button. Background: `bg-zinc-800 dark:bg-zinc-700 text-white`. The bar disappears when `undoAvailable` becomes false (after 30s or after undo click).

    h. **Delete the old collapsible feedback section** (lines 599-655): Remove the `showFeedback` state, the collapsible button, the accordion expand/collapse, and the old textarea + "Regenerate with Feedback" / "Regenerate" buttons. Replace with:
       ```jsx
       {canFeedback && isAITextLesson && (isCompleted || isFailed) && !generating && (
         <FeedbackSection
           onSubmit={(fb) => handleGenerate(fb)}
           creditsRemaining={creditsRemaining}
           disabled={generating}
           generating={generating}
         />
       )}
       ```
       Where `isAITextLesson` = `lesson.contentType === "text" && isOwnedCourse` (AI-generated text lessons only, not YouTube video lessons).

    i. **Cleanup**: Remove the `showFeedback` state variable and the `setShowFeedback` calls. The `feedback` state variable is no longer needed at the page level (FeedbackSection manages its own textarea state). Remove the `ModelSelector` import and `modelValue` state if the feedback flow no longer exposes model selection (the research and context do not mention model selection in the new design -- it uses the default provider). If removing model selection: strip `tier`/`provider`/`model` from the `handleGenerate` payload for feedback-triggered regeneration (use defaults). Keep model selection for the initial "Generate" button on skeleton lessons (canEdit-only flow).

    j. **Cleanup polling on unmount**: Ensure the undo timer is also cleaned up on unmount.
